## 3. 「底包」语义（防误解）

| 是 | 不是 |
|---|---|
| **门禁血统 / 策略根**：非 Tensor → `UNSUPPORTED`，不标「可尝试」 | 整棵工作树永久钉死在 `3146d2538` 不允许任何 diff |
| **叠加纪律**：只拣已证明的好补丁（UI/软化/诊断/通道韧性等） | 自动继承 3.0.5～3.0.7 的「软件开门 / 可尝试」产品语义 |
| **对照基线**：评估爆炸半径时以 3.0.4 为「少踩 OEM 拒写」参照 | GitHub Release 必须重新挂 `v3.0.4`（历史可无 tag） |
| **代码不变量优先**：以 `CompatChecker` + 单测锁死纪律 | 仅靠「git 祖先不含脏 commit」——main 合流后历史里仍可能看见脏 SHA |

> 诚实说明：`main` 合流后，`ce1130ae7`（3.0.5 非 Tensor VoWiFi 软件开门）**仍可能是 HEAD 的 git 祖先**；底包纪律靠 **运行时门禁 + 单测** 守住，不能只靠 `merge-base --is-ancestor` 证伪脏路径。

## 4. 硬不变量（必须守）

1. **`CompatChecker.resolveSupportLevel`**：`!tensor → SupportLevel.UNSUPPORTED`（先于通道/SDK 分支）。  
   证据文件：`app/src/main/java/com/oneims/app/core/CompatChecker.kt`。
2. **单测**：`CompatAndSocPolicyTest.resolveSupportLevel_nonTensorIsUnsupported` 及「非 Tensor 压过缺通道」用例必须绿。
3. **文案**：非 Tensor 劝退语义对齐 3.0.4 bloodline（中/英 `compat_advice_*` / nontensor 文案不得暗示「可强开」）。
4. **产品优先级不冲突**：底包纪律与 Pixel-first（P0）并存——国产机软化属于 P1 容错，不得借软化把非 Tensor 重新标成「可尝试」。

## 6. 允许叠加（好 · 须单独举证）

在 3.0.4 根之上，**可以**继续保留/拣入（须可回滚、可验证）：

- UI：三态通道 / 矮屏紧凑 / 假就绪硬门禁 / Hero 吃字等体验补丁  
- 国产 VoWIFI OEM 软化、Broker persistent→temporary、详细诊断日志（防崩 ≠ 鼓励非 Tensor 强开）  
- OneKuku 通道韧性（Watchdog / 配对 FGS / OneBridge）——**不含**已废止的 CARE_MIN 迷你版（见 `docs/changes/2026-07-30-abolish-onekuku-mini-care-min.md`）  

- R2：砍三项独家运行时路径（能力迁 OneTools）

叠加原则：**先问是否削弱 3.0.4 门禁或不变量；再问是否服务 Pixel P0。**
