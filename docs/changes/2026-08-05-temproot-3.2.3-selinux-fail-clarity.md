# 3.2.3：一键失败根因与诚实判定

## 真机证据（comet / CP2A.260705.006 / Lite）

- `getenforce` → **Enforcing**
- `/data/local/tmp/su -c id` → `su: connect daemon: Permission denied`
- AVC：`temp_su.sock` write denied（`untrusted_app` 与 `shell` 皆拒，`permissive=0`）

## App 侧修复（本版）

1. `ShizukuTempRootShell`：LD_PRELOAD / VERIFY **必须**输出 uid=0，禁止「exit=0 + 日志」假成功  
2. 失败分类：`selinux_blocks_su_daemon` 等 + 人话 snackbar  
3. 版本 **3.2.3 / 84**

## 未解（so / 内核面）

Enforcing 下 exploit 需先打通并放宽/切 Permissive，否则 su daemon 不可达——这超出 App 文案修复，需 OneSo-factory 侧 so 在该 Build 上的成功率。
