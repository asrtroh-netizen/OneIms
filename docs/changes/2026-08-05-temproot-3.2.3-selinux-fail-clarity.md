# 3.2.3：一键失败根因、诚实判定与自动重试

## 真机证据（comet / CP2A.260705.006 / Lite）

- `getenforce` → **Enforcing**
- `/data/local/tmp/su` 与破损 `temp_su.sock` 残留；`su -c id` → `su: connect daemon: Permission denied`
- AVC：`temp_su.sock` write denied（`untrusted_app` 与 `shell` 皆拒，`permissive=0`）
- `LD_PRELOAD=.../preload-comet.so /system/bin/id` 常卡在 `slide attempt 1`（与 OneSo-factory README「第一轮可能卡 CFI，杀掉重试」一致）
- 用户点击时 log：`OneIMS-TempRootAct: start via=shizuku ... so=remote:...` 后失败

## App 侧修复（本版）

1. `ShizukuTempRootShell`：LD_PRELOAD / VERIFY **必须**输出 uid=0，禁止「exit=0 + 日志」假成功  
2. 失败分类：`selinux_blocks_su_daemon` 等 + 人话 snackbar（含 `timeout`）  
3. 一键前 `KILL_STUCK_PRELOAD`，**最多 2 轮** exploit（杀残留再跑）  
4. Lite 跳过 app 内 `ProcessBuilder(su)` 验活（只造 AVC，改走 Shizuku VERIFY）  
5. 版本 **3.2.3 / 84**；制品 `OneIms-Lite-Shizuku-3.2.3.apk`

## 未解（so / 内核面）

Enforcing 下需 exploit 完整跑通并重建 daemon（通常顺带 selinux→Permissive）。残留 root 拥有的 `su`/`temp_su.sock` shell 删不掉；若连续卡住，可重启后再用 3.2.3 一键（自动杀残留+重试）。成功率最终仍依赖 OneSo-factory 对该 Build 的 so。
