# 2026-08-04 · FNHOME 网段 31→2 后遗漏修复（NPS TMI）

## 背景

FNHOME / HaloXFN 本机 IP 已从 `192.168.31.2` 改为 `192.168.2.2`；NPS「狗窝」多数隧道已改为 `192.168.2.2`。VPS nginx 反代不在本轮范围。

## 采证结论

| 检查项 | 结果 |
|---|---|
| HaloXFN `enp1s0-ovs` | `192.168.2.2/24`，网关 `192.168.2.1`，DNS `192.168.2.1` |
| 本机配置残留 `192.168.31` | **无**（仅历史日志：npc / 迅雷） |
| 本地服务 | `:9999/:3002/:2048/:81` HTTP 200；mihomo `/version` 正常；出网百度/Google 正常 |
| NPS 客户端「狗窝」 | 在线，`vkey` 与本机 `npc.conf` 一致 |
| NPS 狗窝 TCP 隧道 | 除一条外均已指向 `192.168.2.2` |

## 唯一漏改

| 项 | 旧值 | 新值 |
|---|---|---|
| NPS TCP `id=44` / 公网端口 `2323` / 备注 `TMI`（狗窝） | `192.168.31.1:80` | `192.168.2.1:80`（小米 BE6500） |

说明：`2323` 是经狗窝穿透访问上级小米路由后台的隧道；网段搬家后路由管理地址已是 `192.168.2.1`，不是飞牛 `2.2`。

## 本轮改动

- **仅**修改阿里云 NPS 上述一条隧道目标；未改单位/丫头客户端，未改 FNHOME 本机配置（本机已对齐）。
- 改后全量 TCP 扫描：`192.168.31.*` **0 条**。

## 验证

| 检查 | 结果 |
|---|---|
| NPS 复核 `id=44` target | `192.168.2.1:80`，RunStatus=true；全量 TCP 无 `192.168.31.*` |
| FNHOME → `http://192.168.2.1/` | HTTP 200，正文含「小米」 |
| 本机 `2.2:9999/3002/2048/81` | 均为 HTTP 200 |
| 公网 `http://8.137.155.86:9999/` / `http://hfs.itt.fan/` / `:81` | 均为 HTTP 200 |
| 公网 `:2323` 无 Host | HTTP 500（小米 nginx 拒错 Host，属旧行为） |
| 公网 `:2323` + `Host: miwifi.com` | HTTP 200，小米路由页 |

## 回滚

NPS 后台将 `TMI`/`2323` 目标改回 `192.168.31.1:80`（仅当旧网段仍存在时有意义；当前家网已无 31 段则回滚无用）。

## 范围外

- VPS nginx / `dh.itt.fan` 根路径 502（见 `2026-08-04-fnhome-ange-panel-public-81.md`）
- 单位、丫头、TTFN 任意配置
- Docker socket 权限（Halo 用户 `docker ps` permission denied，不影响已监听服务）
