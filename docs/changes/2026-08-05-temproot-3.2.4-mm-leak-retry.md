# 3.2.4：一键仍失败续排 — mm_struct leak + 多轮重试

## 不是「会话卡住」

上一轮已交付 3.2.3（诚实判定 / SELinux 文案 / 双轮重试）。本轮用户问「还失败 / 卡住了？」——**面板会话未假死**；真机仍无 uid=0。

## 本轮真机证据（comet / CP2A.260705.006 / Lite）

| 检查 | 结果 |
|---|---|
| 包版本（改前） | `3.2.3-onelink` (84) |
| Shizuku | `shizuku_server` 在跑，V15.0.0 |
| so | `/data/local/tmp/preload-comet.so` SHA 前缀 `e74cbc7d…`（与 README-ADAPT 曾成功制品一致） |
| 180s LD_PRELOAD | 反复 `KernelSnitch mm_struct leak failed` / `prepare_kernel_page retry`；**无 uid=0** |
| 结束后 | `getenforce=Enforcing`；`su: connect daemon: Permission denied` |

说明：同 so 历史上曾成功（README-ADAPT）；失败表象「SELinux 挡 sock」常常是 **exploit 没跑完 → 从未 setenforce/起 daemon** 的下游症状。

## App 侧改动（3.2.4 / 85）

1. exploit 自动重试 **2 → 4**，轮间 gap 3s + 每轮前杀残留  
2. 失败分类优先 `kernel_mm_leak_failed`（盖过 SELinux 噪声）  
3. 对应人话 snackbar
