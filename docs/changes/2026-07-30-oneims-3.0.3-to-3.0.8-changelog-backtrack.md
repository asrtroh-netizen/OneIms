## 稳定性锚点更正（用户现场）

> **用户澄清：最稳是 3.0.4，关键证据是「小米不闪退」。**  
> 下文以 `3146d2538`（3.0.4 / vc74）为基线；3.0.3 仅作更早参照。

### 为何 3.0.4 在小米上更不易闪退

| 事实 | 证据 |
|---|---|
| 非 Tensor 体检结论 = **UNSUPPORTED** | `CompatChecker` @ `3146d2538`：`!tensor -> UNSUPPORTED` |
| 用户更少强开国产 VoWiFi 拒写路径 | 同上；3.0.6 才改为非 Tensor → **DEGRADED（可尝试）**（`afdbda2cc`） |
| 尚无「小米系 soft-fail / HyperOS 专用」补丁 | `OemDeviceCompat` / 小米软化首次出现在 3.0.8 的 `e6628c6c8` |
| 3.0.4 已含沙盒默认开 + 更新屏蔽 | 说明这两项**不是**「小米闪退从无到有」的主因 |

### 3.0.4 之后谁更像「引入小米闪退」

1. **3.0.5（高嫌疑 · 行为放大）**  
   - `ce1130ae7`：非 Tensor VoWiFi **软件开门**（同日曾短暂硬拒又撤销，最终鼓励尝试）  
   - 小米用户更常点到 key=28 / WFC，触发 HyperOS 拒写 / SecurityException 面  
2. **3.0.6（高嫌疑 · 策略 + 结构）**  
   - Compat：非 Tensor 从「不支持」→「降级可试」  
   - 仅软化 key **26/27**（一加向）；**未**软化小米关键的 **28/68**  
   - OneKuku V15 后台面变大（次要）  
3. **3.0.7**  
   - 主要修一加假就绪 / UI；非小米主因  
4. **3.0.8（补丁向 · 承认 HyperOS 崩面）**  
   - 文档原文：`群友反馈：小米 / HyperOS 上 OneIMS 闪退`（`docs/changes/2026-07-30-xiaomi-compat-diag-logger.md`）  
   - `e6628c6c8`：小米系 soft key=28（+全机 26/27/68）；CarrierConfig 回读软超时  
   - `c8909e25b`：Broker `persistent=true` 拒写同会话降临时（防 SecurityException 冒到 UI）

### 因果链（证据等级）

```text
3.0.4：体检劝退非 Tensor → 小米少踩 VoWiFi/拒写硬路径 → 现场「不闪退」
   ↓ 3.0.5 开门 + 3.0.6 标「可试」且只软化 26/27
小米点应用 → key=28/68 或 persistent 拒写抛到进程 → HyperOS 闪退（群友反馈）
   ↓ 3.0.8 软化 + Broker 降临时
意图止血；真机是否已彻底消除 → NOT RUN（需导出详细日志）
```

### 3.0.3 备注（次要）

覆盖发包说明见 `docs/changes/2026-07-25-release-3.0.3-overwrite-sandbox.md`（沙盒旁路默认关）。  
相对 3.0.4，3.0.3 **没有**默认开更新屏蔽 / 沙盒默认开；但用户现场锚点已明确指向 **3.0.4 + 小米不闪退**。

## 分段变化（相对上一 release bump）

### 3.0.3 → 3.0.4（+1035 / -15，风险面最大）

主线（README What's New 一致）：

1. **首页「持久性 VoLTE/NR」**：沙盒旁路 **默认开**（相对 3.0.3 覆盖包「默认关」是关键语义翻转）
2. **VoNR 写入 NR 可用性**：便于系统设置露出 VoNR
3. **系统更新屏蔽（独家，默认开）**：组件禁用 + settings + Magisk hosts 挡 OTA（best-effort）
4. 另含：VOIMS opt-in key 68、沙盒 Instrumentation / Provider 整套落地

稳定性含义：默认行为从「少动手」变成「尽量真持久 + 尽量挡更新」——权限/组件侧副作用面明显变大。

### 3.0.4 → 3.0.5（+163 / -1053，产品面收敛）

1. 非 Tensor（含联发科等）**放开 VoWiFi 写入尝试**（是否上栏仍看 OEM）
2. 独家页去掉三项显示/切卡入口，保留身份/国家码/守护/APN/专家编辑
3. 净删大量 Experimental 展示逻辑（行数减少主要来自这里）

稳定性含义：写入门更宽（国产机更敢写），但 UI 入口收敛。

### 3.0.5 → 3.0.6（+1609 / -494，改动量最大）

主线：

1. 首页紧凑 + 通道 Hero **三态**（未激活 / 激活中 / 就绪）
2. **OneKuku 对齐 Shizuku V15 开机韧性**：配对码进 FGS、binder 重试、Wi‑Fi/解锁续跑、可选 Watchdog（默认开）
3. IMS：一加等对 key 26/27 拒写 **软成功**；高通兼容从「一刀切不支持」降级为可尝试
4. 新增 `ProvisioningWritePolicy` 等写入策略层

稳定性含义：方向是「更抗崩 / 更抗掉线」，但 OneKuku 后台面（FGS/Watchdog/Receiver）显著变复杂——这是 3.0.3→3.0.8 最大结构跃迁。

### 3.0.6 → 3.0.7（+110 / -85，稳定性补丁）

1. 修 OneKuku「假就绪」与一加「点应用闪退」
2. 修首页 StatusHero 标题被胶囊吃字

稳定性含义：针对 3.0.6 回归的小修，风险低。

### 3.0.7 → 3.0.8（+814 / -49，兼容/排障）

1. Pixel VoWIFI / 通信开机自启定为 P0 硬保证；国产 OEM VoWIFI **统一门控**（含三星/荣耀）
2. Broker：`persistent=true` 拒写同会话降临时（对齐 pixel-volte-patch，防闪退）
3. 小米等拒写软化；排障页「导出详细日志」（`DiagFileLogger`）
4. Pixel VoLTE 硬、VoIMS opt-in 可 soft-fail

稳定性含义：偏防崩与可观测；但「软成功 / 降临时」会让体感成功 ≠ 重启后仍持久——排障时要对照诊断标签。

## 稳定性对照结论（给「想回到 3.0.3 手感」）

若用户觉得 3.0.3 更稳，优先怀疑这三刀（按爆炸半径）：

1. **3.0.4 默认开沙盒持久 + 默认开更新屏蔽**（系统组件/设置/hosts）
2. **3.0.6 OneKuku V15 级后台韧性重写**（FGS / Watchdog / 多 Receiver）
3. **3.0.5~3.0.8 写入策略软化与 OEM 门控**（少闪退，但成功语义变宽）

3.0.7 / 3.0.8 多数是在上述大面上做崩溃与假态修补，而不是回到 3.0.3 的「小面默认关」模型。
