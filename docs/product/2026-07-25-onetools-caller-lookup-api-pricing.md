## 3. 用量粗算（百度 SPNS）

假设「仅本地未命中才联网」，每成功查号 1 次扣 1 次：

| 场景 | 日均联网查号 | 年用量 | 建议量包 |
|---|---|---|---|
| 自用 Pixel 1～2 台 | 20～50 | ~1～2 万 | **1 万次 ¥200** 可能够一年 |
| 小范围内测 50 人 | 200～500 | ~7～18 万 | **10 万次 ¥1,800** |
| 公开分发 5k DAU（保守） | 5k～20k | 极高 | 需 100 万+ 或自建缓存/本地库 |

**必做工程：** 服务端代理（Key 不下发 APK）、结果缓存、超时（≤3s）、失败放行、隐私说明（只传号码）。

## 4. 与 OneCaller 架构契合

```
本地规则 → onespam（精确/前缀）→（未命中且允许联网）→ 商业 API
                                                    ↓
                              CallerNetworkQuery / ONE_CALLER_QUERY_URL
```

- 归属地：**继续本地 geo**，不要用商业 API 当主路径（贵且多余）  
- 骚扰标签：百度 SPNS 最贴「可采购 + 价目公开」  
- 电话邦「企业来电名片认证」是 **企业给自己打标**，不是给我们查陌生人骚扰库，别混

## 5. 风险与合规

- 个人数据最小化：仅号码；HTTPS；日志脱敏  
- Play / 国内应用商店对来电识别权限敏感，需隐私政策写清第三方  
- Key 必须放自有后端或 One CDN 边缘，禁止进客户端  
- 标签误伤（外卖/快递）要保留白名单（我们已有）
