## 1. 产品约束（采证）

- 产品：面向 Google Pixel 的 IMS 配置 / 诊断 / 修复助手（VoLTE · VoWiFi · VoNR 等）。
- 现状变现：底栏「赞助」页（微信赞赏等，自愿）；另有 DodoPay 支持作者能力沉淀。
- 风险：核心「能打电话 / 能开 VoLTE」若被强锁，社区反噬大；宜 **核心免费、增值付费**。

## 2. 分档原则

| 原则 | 说明 |
|---|---|
| 核心不断粮 | 选卡、写配、诊断、一键恢复系统默认等保底能力保持免费 |
| 付费买时间与体面 | 会员买「更快跟上系统」「更少打扰」「更贴身定制」「身份感」 |
| 可感知差异 | 付费后 3 秒内能感到变化（去赞助 / **专属铭牌** / 优先通道文案） |
| 定制有上限 | Pro 含 **3 次**定制工单；超出按次加购，避免终身无限改需求 |

## 4. Pro「定制 ×3」规则（建议写进用户协议/会员页）

1. **什么算 1 次**：一条可交付的功能/适配需求（含澄清 → 开发 → 你验收通过）。
2. **什么不算消耗**：Bug 反馈、与已购权益无关的咨询、官方已规划的公开功能。
3. **有效期**：建议与 Pro 终身绑定（不设 1 年作废）；若担心囤单，可改为「开通后 24 个月内用完」。
4. **范围边界**：限 OneIMS 产品内（IMS/诊断/显示/通道相关）；不做无关 App、不做无限改 UI 重做。
5. **进度**：会员页展示「剩余 3/2/1/0 次」+ 历史工单状态（待接单/进行中/已交付）。

## 5. 专属铭牌 · 产品定义（UI/UX）

### 5.1 铭牌是什么

- 一枚 **Pro 专属身份条**：展示名（用户可填，如昵称/TG 名）+「OneIMS Pro」徽记 + 可选短编号（如 `#0247`）。
- 定位：**荣誉与归属**，不是功能开关；免费/Plus 看不到同款样式。

### 5.2 建议出现位置（克制，最多 2 处常驻）

| 位置 | 呈现 | 优先级 |
|---|---|---|
| **设置 → 关于 / 会员** | 完整铭牌卡（头像区可选、展示名、编号、剩余定制次数） | P0 必做 |
| **首页 StatusHero 旁** | 小徽章「Pro」+ 展示名一行（可开关「首页显示铭牌」） | P1 |
| 付费成功页 | 庆祝动效一次，铭牌首次点亮 | P0 |
| 诊断报告页眉 | 可选水印式小字（默认关，防打扰） | P2 |

### 5.3 交互与状态

- **开通瞬间**：铭牌从灰态 → 点亮；赞助 Tab 同步隐藏。
- **编辑展示名**：默认开通时用「Pro 成员」；允许修改，建议 **2～12 字**，过滤敏感词；改名不消耗定制次数。
- **空态/未登录核销**：显示「待激活铭牌」+ 恢复购买入口。
- **a11y**：徽记不只靠颜色；`contentDescription` 含「Pro 专属铭牌，展示名 xxx」；动效遵守系统「减少动态效果」。

### 5.4 视觉约束（产品内）

- 跟 OneIMS 现有品牌色，**不要**另起一套紫粉玻璃拟态。
- 铭牌用轻微 elevation + 细描边即可；首页只留小徽章，避免首屏营销感过重。

## 12. 付费后分发 · GitHub 硬约束

> 用户澄清（2026-07-24）：**不是「不想」放 GitHub，是「不能」再把付费产品挂在公开 GitHub 分发。**  
> 再澄清：**不 GitHub ≠ 取消免费**——¥0 免费档仍在；只是安装包改走 TG 等非 GitHub 渠道。  
> 因此公开 GitHub Release 作为正式下载源 = **禁止项**，不是可选偏好。

### 现状（采证）

- 仓库已声明不开源；对外主要是 README + **公开 Release APK**。
- `UpdateChecker` **写死**拉 `api.github.com/.../releases/latest`，且注释写明目标仓必须 Public——付费后迁出时，**更新检查必须一并改掉**，否则会逼仓库继续公开挂包。

### 硬约束下的唯一主路径

| 项 | 要求 |
|---|---|
| 正式 APK | **不得**再挂公开 GitHub Release |
| 源码仓 | Private（开发用）；或公开仓仅文档、无 APK |
| 用户下载 / 更新 | Telegram / 自建下载页 / 对象存储 + 校验（任选，但须非公开 GH Release） |
| 免费档 ¥0 | **保留**：核心 IMS/诊断/恢复仍免费；免费 APK 也可在 TG 公开区发放，只是不走 GitHub |
| 付费 Plus/Pro | **外置核销**（用户自定：微信/支付宝/DodoPay/人工发码等）；不依赖 GitHub，也不强制本轮接应用内完整收银台 |
| 应用内更新 | 换非 GitHub 的 manifest/JSON；禁止继续依赖公开 `releases/latest` |

### App 侧怎么配合（在你「其他方式」付费时）

- 付费页 `MembershipPaywallScreen`：继续展示档位与权益；CTA 可改为「去购买 / 已购买，输入兑换码」等（按你最终核销方式改文案）。
- 开通成功后：本地写入会员凭证 → 去赞助页、点亮铭牌、放开独家门闸。
- **本轮不实现**完整第三方支付 SDK，除非你指定具体通道让哥哥我对接。

### 迁移顺序（必须按序）

1. **先定新下载真源**（TG 文件 / 网盘 / 自建 URL）并公示 SHA256 + 签名指纹  
2. **改 `UpdateChecker`** 指向新源（否则旧客户端仍打公开 GH）  
3. README 改「仅 TG/官网获取」；公开 Release **撤包或标已迁移**  
4. 仓库改 Private 或 Archive 公开页  
5. TG 发迁移公告（旧链失效时间写清）

### 过渡

- 允许 **短过渡期**（如 7～14 天）旧链只读提示「已迁移」，但新版本 **不得**再上传公开 Release。  
- 「继续公开挂最新包只靠应用内付费」在本硬约束下 **不可选**。
